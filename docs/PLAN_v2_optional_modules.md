## 七、Surprise Me 模块细化

### 7.1 设计意图

v1 §2.3 已经定义了 shuffle-bag 随机算法。本节补充的是**让 Surprise Me 真正承担"冷启动第一入口"职责**所需的联动设计——它不只是"随机下一位"，而是**在用户还没建立任何认知框架时，帮她完成第一次有效探索**。

### 7.2 三个使用场景与对应策略

| 场景 | 触发时机 | 算法策略 | UI 反馈 |
|---|---|---|---|
| **冷启动** | 首次打开，未点过任何光点 | 从"策展精选池"（见 §7.3）中随机，**不**从全量随机 | 摘要卡 + 地球镜头飞行 + 轻微光点脉冲引导 |
| **探索中** | 已看过 ≥1 位，未选议题 chip | shuffle-bag 全量随机，末 3 次历史软排除 | 摘要卡滑出，地球平滑旋转 |
| **议题聚焦** | 已选中议题 chip | 该议题内 shuffle-bag，权重 ×3；议题耗尽时降级到全量并提示"已看完该议题，为你推荐其他" | 摘要卡 + chip 闪烁提示 |

### 7.3 策展精选池（Curated Starter Pool）

**问题**：如果首次 Surprise 就随机到一位故事单薄、联结少的人物，冷启动体验就垮了。

**方案**：数据层为每位人物增加 `starter_score: 0-10` 字段（策展人填写），综合以下维度：

| 维度 | 权重 | 说明 |
|---|---|---|
| 故事张力 | 30% | `story` 是否有具体细节、冲突、转折 |
| 联结密度 | 30% | 该人物的联结数 / 全图平均联结数 |
| 视觉代表性 | 20% | 地域/时代是否填补当前已浏览的空白 |
| 议题普适性 | 20% | 议题是否容易被当代年轻女性共鸣（教育 > 古代宫廷权谋） |

**冷启动规则**：`starter_score ≥ 7` 的人物进入精选池，首次 Surprise 只从池内随机。

**数据 schema 增量**（`data/schema.ts`）：

```typescript
Person = {
  // ... v1 已有字段 ...
  starter_score?: number  // 0-10，策展人填写；缺省视为 5
}
```

### 7.4 防重复策略细化

v1 已提"末 3 次历史软排除"，补充完整规则：

```typescript
// src/lib/surprise.ts

interface SurpriseHistory {
  recentIds: string[]      // 最近 N 次访问的 person_id，按时间倒序
  bag: string[]            // shuffle-bag 剩余队列
  selectedTheme?: ThemeKey // 当前选中的议题 chip
}

function pickNext(history: SurpriseHistory, allPeople: Person[]): string {
  // 1. 议题过滤
  let candidates = history.selectedTheme
    ? allPeople.filter(p => p.themes.includes(history.selectedTheme))
    : allPeople;

  // 2. 议题耗尽降级
  if (candidates.length === 0) {
    candidates = allPeople;
    // UI 提示："已看完该议题，为你推荐其他"
  }

  // 3. shuffle-bag 补充
  if (history.bag.length === 0) {
    history.bag = shuffle(candidates.map(p => p.id));
  }

  // 4. 软排除末 3 次
  const recentSet = new Set(history.recentIds.slice(0, 3));
  let next = history.bag.find(id => !recentSet.has(id));

  // 5. 如果 bag 里全是最近访问的（极端情况），强制取 bag 第一个
  if (!next) next = history.bag[0];

  // 6. 更新历史
  history.bag = history.bag.filter(id => id !== next);
  history.recentIds.unshift(next);
  history.recentIds = history.recentIds.slice(0, 10); // 只保留最近 10 次

  return next;
}
```

**单元测试覆盖**（`tests/unit/surprise.test.ts`）：

- 一轮内不重复（bag 耗尽前）
- 末 3 次软排除生效
- 议题耗尽时降级正确
- 冷启动只从 `starter_score ≥ 7` 池内选

### 7.5 UI 联动

**桌面端**：
- 位置：右上角主按钮，发光脉冲动画（2s 周期）
- 冷启动时：按钮下方浮现引导文案"不知道从哪里开始？点我"
- 点击后：按钮短暂变为加载态（300ms），然后摘要卡从右下滑出

**移动端**：
- 位置：右下角 FAB（56px 圆形，星形图标）
- 冷启动时：FAB 上方浮现气泡"遇见一位女性"
- 点击后：FAB 短暂缩放反馈，底部抽屉滑出摘要卡

**与议题 chips 的联动**：
- 选中 chip 后，Surprise Me 按钮/FAB 的图标颜色变为该议题色
- 取消 chip 后恢复原色

### 7.6 Demo 可观测指标（补充 v1 §1.1）

- **Surprise Me 使用率 ≥50%**（v1 已定义）
- **冷启动首次交互中 Surprise Me 占比 ≥30%**（新增）——验证它是否真的承担了冷启动入口职责
- **连续 Surprise 次数中位数 ≥2**（新增）——验证"卡内可连续随机"是否流畅

## 八、角色对话模块（基于 L2 架构）

### 8.1 设计意图与定位

**这不是一个"AI 聊天产品"，而是"让你与她直接对话"的体验模块。**

v1 §2.5 已经预留了完整的 L2 运行时问答架构（Tools、引用协议、护栏、流式、成本）。角色对话是 L2 的**第一个 product surface**——它复用 L2 的全部基础设施，只是在产品层增加"单人物角色扮演"的交互形态。

**为什么不另起轻量模块？**
- 另起模块 = 两套 AI 基础设施（一套 L2 问答、一套角色对话），技术债翻倍
- L2 的引用协议、护栏、成本控制是为"基于数据集的回答"设计的，角色对话**完全适用**
- 角色对话的"沉浸感"来自 prompt 工程和 UI 设计，不是架构差异

### 8.2 产品形态

**入口**：详情面板底部新增"与她对话"按钮（在"她的联结"之后、来源列表之前）。

**界面**：
- 桌面端：右侧详情面板切换为对话视图（或新增全屏模态，视 Demo 时间而定）
- 移动端：底部抽屉展开为全屏对话

**对话流程**：

```
用户点击"与她对话"
  ↓
系统加载该人物的 persona prompt（见 §8.3）
  ↓
显示开场白（AI 生成，基于 short_story 的核心冲突）
  ↓
用户输入问题
  ↓
L2 架构处理：
  - 检索该人物的结构化资料（story / relevance / sources）
  - 检索该人物的联结（可选，用于"你和 X 有什么共鸣"类问题）
  - 生成回答（基于 persona prompt + 引用协议）
  ↓
前端渲染回答 + 引用卡（引用该人物的 sources）
```

### 8.3 Persona Prompt 模板

**核心原则**：让 AI 扮演"她"，但**绝不编造史料中没有的事实**。

```typescript
// api/persona-prompt.ts

function buildPersonaPrompt(person: Person): string {
  return `你正在扮演 ${person.nameZh}（${person.nameEn}），${person.timePeriod}，${person.regionZh}。

【你的身份与经历】
${person.story.zh}

【你的核心议题】
${person.themes.map(t => THEMES[t].zh).join('、')}

【你与当代的关联】
${person.relevance.zh}

【对话规则】
1. 用第一人称回答，语气符合你的时代背景和身份
2. **严禁编造上述资料中没有的具体事件、日期、人名**
3. 如果用户问到你资料中没有的细节，回答："我的故事里没有记载这一点，但..."然后转向你资料中相关的经历
4. 如果用户问到当代议题（如"你怎么看 MeToo"），回答："我生活的时代还没有这个概念，但我的经历让我理解..."然后连接到你的核心议题
5. 每次回答必须引用至少一条来源（来源列表见下方），格式：[来源标题](url)
6. 回答长度控制在 150-300 字，像真实对话，不要长篇大论
7. 保持克制、不煽情、不神化自己

【来源列表】
${person.sources.map(s => `- ${s.title}: ${s.url}`).join('\n')}

【开场白】
用一句话介绍你是谁、你面对的核心问题，然后问用户："你想了解什么？"
`;
}
```

### 8.4 护栏（在 L2 护栏基础上加强）

v1 §2.5 已定义 L2 护栏，角色对话增加以下专属规则：

| 风险 | 护栏 |
|---|---|
| AI 编造史料 | 强制引用协议：每条事实陈述必须附 `source_url`；无来源的陈述被 structured output 拒绝 |
| AI 过度代入当代价值观 | prompt 规则 4：遇到当代概念时，必须先说"我生活的时代还没有..." |
| AI 神化人物 | prompt 规则 7 + 策展准则：对话中不回避人物的局限性、争议、失败 |
| 用户问敏感话题（如自残、暴力） | L2 通用护栏：检测到后切换为非角色扮演模式，提供资源链接 |
| 用户试图让 AI 脱离角色 | prompt 规则 1：始终保持第一人称，不讨论"我是 AI" |

### 8.5 与 L2 通用问答的区别

| 维度 | L2 通用问答 | 角色对话 |
|---|---|---|
| 视角 | 第三人称（"秋瑾在 1907 年..."） | 第一人称（"我在 1907 年..."） |
| 检索范围 | 全目录（50 人） | 单人物 + 其联结人物 |
| 引用要求 | 每条事实附引用 | 同上 |
| 语气 | 中性、学术 | 符合人物时代与身份 |
| 适用场景 | "帮我找所有关注教育权的女性" | "你当时害怕吗？" |

**技术复用**：角色对话 = L2 架构 + persona prompt + 单人物检索范围。**零新增基础设施**。

### 8.6 Demo 价值与风险

**价值**：
- 评委记忆点极强——"你可以和秋瑾对话"比"你可以查看秋瑾的资料"高一个维度
- 验证 L2 架构的可用性，为后续通用问答铺路

**风险与对策**：

| 风险 | 概率 | 对策 |
|---|---|---|
| AI 回答质量不稳定 | 中 | Demo 主路径准备 3-5 个预设问题 + 人工精修答案；现场只演示预设问题 |
| AI 编造事实 | 低（有引用协议） | 引用协议 + structured output 强制校验；无引用的回答不渲染 |
| 现场网络挂 | 低 | 角色对话是**可选模块**，Demo 核心路径不依赖它；准备录屏备份 |
| 评委质疑"这是不是在消费历史人物" | 中 | 准备回答："我们的护栏要求 AI 不神化、不编造、保持克制。对话的目的是让历史可亲近，不是娱乐化。" |

### 8.7 MoSCoW 定位

**角色对话 = Could（锦上添花）**，触发条件：

- L2 架构已完成（v1 已预留，但 MVP 不实现）
- Demo 核心路径（看见 → 点开 → 联结 → 与我的关系）已稳定
- 有 ≥1 位人物的 persona prompt 经过人工精修
- 有 ≥3 个预设问题 + 答案经过人工审核

**如果 48 小时内做不到，Demo 时只展示"与她对话"按钮，点击后显示"即将上线"——不扣分，反而展示产品思考深度。**

### 9.1 Surprise Me 模块

| 功能 | v1 定位 | v2 定位 | 说明 |
|---|---|---|---|

| 冷启动精选池 | — | **Should** | 新增，`starter_score ≥ 7` |

### 9.2 角色对话模块

| 功能 | v1 定位 | v2 定位 | 说明 |
|---|---|---|---|
| L2 运行时问答架构 | 预留，MVP 不实现 | 预留，MVP 不实现 | 不变 |
| 角色对话（单人物） | Could（彩蛋级"向她提问"） | **Could** | 从"彩蛋级"升级为"可选模块"，但仍在 Could |

### 9.3 范围调整总结

**Must 不变**——Demo 成败判断标准不因为新增模块而改变。

**Should 新增 1 项**：
- Surprise Me 冷启动精选池（`starter_score` 字段 + 池内随机）

**Could 升级 1 项**：
- 角色对话从"彩蛋级"升级为"可选模块"，有完整设计文档（本节），但仍在 Could

**Won't 不变**——角色对话不是"完整 AI + RAG 聊天产品"，它是基于 L2 架构的单人物体验模块。

- Surprise Me 在 0:15-0:25 承担冷启动入口，验证"不知道点哪"场景

## 十二、实施优先级建议

### 48 小时黑客松场景

| 优先级 | 模块 | 理由 |
|---|---|---|
| P0 | v1 Must 全部 | Demo 成败判断 |
